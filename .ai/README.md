# .ai — Agent-Neutral Rules, Skills & Connectors

This directory contains **shared AI agent resources** that are not tied to any specific coding tool.
The same rules, skills and connectors work with Claude Code, Kiro, Cursor, GitHub Copilot,
Antigravity, or any other agent that can read markdown and execute shell commands.

Three kinds of thing live here, and the distinction matters:

| | What it is | Delivered by |
| --- | --- | --- |
| [`rules/`](./rules/README.md) | Standing conventions — how we branch, commit, style code, treat environments | A pointer file per agent (`AGENTS.md`, `CLAUDE.md`, …) → [`CONTRIBUTING.md`](../CONTRIBUTING.md) |
| [`skills/`](./skills/README.md) | Procedures for multi-step jobs — review an MR, cut a release, fix a vulnerability | A thin wrapper per agent, generated by `yarn skills:sync` |
| `connectors/` | Executable access to external services, run from the shell | Called by path from a skill, or by hand |

Rules always apply. A skill applies when its trigger matches. A connector is a tool either
one reaches for.

## Credentials — Root .env

All connectors load their credentials directly from the **root `.env` file** (created from `example.env` at the workspace root). This keeps all API tokens, connection strings, and environments centralised in one place.

## Connectors

Each connector is a self-contained Node.js `.mjs` script. No build step, no dependencies beyond Node 18+.
Run them directly:

```bash
node .ai/connectors/grafana/get-available.mjs
node .ai/connectors/grafana/search-logs.mjs --env uat --service my-service --search "error"
node .ai/connectors/grafana/trace-id.mjs --trace-id 01M0J6EYRY4TFEPR9PHJZ1QHPF --env test
```

All connectors output JSON to stdout and errors to stderr.

## Rules and skills — one source, generated wrappers

Each agent reads its instructions from a different conventional path. Rather than maintaining
a copy per agent by hand, the per-agent files are **generated** from the canonical ones:

| Tool               | Rules pointer                                | Skill wrapper                          |
| ------------------ | -------------------------------------------- | -------------------------------------- |
| *(any)*            | `AGENTS.md`                                  | —                                      |
| **Claude Code**    | `CLAUDE.md`                                  | `.claude/commands/<name>.md` → `/<name>` |
| **Antigravity**    | `.agents/AGENTS.md`                          | `.agents/skills/<name>/SKILL.md`       |
| **GitHub Copilot** | `.github/copilot-instructions.md`            | `.github/skills/<name>/SKILL.md`       |
| **Kiro**           | `.kiro/steering/00-workspace-rules.md`       | `.kiro/skills/<name>/SKILL.md`         |
| **Cursor**         | `.cursor/rules/workspace-rules.md`           | —                                      |

```bash
yarn rules:sync      # regenerate the rule pointers
yarn skills:sync     # regenerate the skill wrappers from canonical frontmatter
yarn agents:check    # verify nothing has drifted — use in CI
```

**Do not hand-edit a generated file.** Hand-copied wrappers drift, and the drift is invisible:
before the generator existed, the same skill was named `Debug & Report` in one wrapper and
`debug-and-report` in another, with different descriptions — so it *triggered differently
depending on which agent you asked*.

The canonical source of truth always lives here in `.ai/rules/` and `.ai/skills/`.

## MCP vs Connectors (Tool Execution Approaches)

This workspace supports two distinct approaches for providing executable tools to AI agents:

1. **Model Context Protocol (MCP) Server**: A persistent stdio server (running under `./mcp`) that exposes tools to the agent directly via the protocol.
2. **Connectors**: Standalone Node.js scripts (running under `.ai/connectors`) executed by the agent via terminal shell commands.

These approaches can be used individually, or simultaneously. To simplify credential management, **both approaches share the root `.env` file** as the single source of truth for secrets, PATs, and API tokens.

### Rule of Thumb: Where to Put Executable Functionality?

When adding a new capability, use the following rules to decide between MCP and Connectors:

* **Definitely a Connector**: If the functionality is used *only once* or is highly specific to a single, isolated skill (e.g., a specific custom migration or script used by a single tutorial).
* **Definitely in the MCP Server**: If the functionality is used *frequently* across many different tasks (e.g., fetching general Jira tickets, querying MongoDB databases, retrying GitLab pipeline jobs).
`trace-id.mjs` is the instructive exception to that split: it exists in **both** forms. The
reconstruction engine lives once in `mcp/src/grafana/trace/`, and the connector imports it rather
than shelling out to the MCP server or duplicating the logic. An agent gets it as a tool; a human
gets it as a CLI; neither can disagree with the other about what a trace means.

* **Arguable Cases**: For other cases, decide on a case-by-case basis keeping in mind:
  * *Overloading the MCP*: Permanently consumes the agent's model context window because all active tool schemas are loaded into the LLM system prompt.
  * *Overloading Connectors*: Makes tool discovery and invocation more difficult. The agent has to list directories, parse README instructions, and construct shell commands, which can also consume context and introduce execution errors.

## Adding a New Skill

1. Create `.ai/skills/<skill-name>/SKILL.md` with `name` and `description` frontmatter — the
   description is the trigger, so write concrete phrasings the user would actually say.
2. Run `yarn skills:sync` to generate the four wrappers.
3. Add a row to [`.ai/skills/README.md`](./skills/README.md) and to
   [`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Adding a New Rule

1. Create `.ai/rules/<topic>.md`.
2. List it in [`.ai/rules/README.md`](./rules/README.md), in the ordered list at the top of
   `scripts/sync-agent-rules.mjs`, and in [`CONTRIBUTING.md`](../CONTRIBUTING.md).
3. Run `yarn rules:sync`.

## Adding a New Connector

1. Create `.ai/connectors/<service>/` with your `.mjs` scripts.
2. Add credentials shape to `connectors/env.json.example`.
3. Document the connector in the structure above.
